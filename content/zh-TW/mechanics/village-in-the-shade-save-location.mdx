## 《Village in the Shade》存檔位置在 Windows 上通常位於何處

大多數中小型 PC 遊戲都建立在少數幾款引擎之一上，而每款引擎都有自家儲存檔案的習慣。與其盲目搜尋，不如先辨識引擎——檔案路徑中的資料夾名稱通常會透露線索——再檢查對應位置。

下表列出常見位置。請把它們當成起點，而非保證：開發者可以覆寫任何預設值，而且遊戲的資料夾名稱可能與商店標題略有不同。

| 引擎／框架 | 常見 Windows 路徑 |
|---|---|
| Unity | `%USERPROFILE%\AppData\LocalLow\<Studio>\<Game>` |
| Unreal Engine | `%LOCALAPPDATA%\<Game>\Saved\SaveGames` |
| Godot | `%APPDATA%\<Game>` 或 `%APPDATA%\Godot\app_userdata\<Game>` |
| GameMaker | `%LOCALAPPDATA%\<Game>` |
| RPG Maker MV/MZ | `%APPDATA%\<Game>` 或執行檔旁的 `save` 資料夾 |
| Steam Cloud wrapper | `Steam\userdata\<AccountID>\<AppID>\remote` |

這裡有兩個快速捷徑可節省時間。按下 **Win + R**，輸入 `%appdata%` 或 `%localappdata%`，直接跳到 Roaming 或 Local AppData 資料夾。接著依 **修改日期** 排序——你上次儲存當下有所變動的資料夾，幾乎肯定就是你要找的那一個。

### 也要檢查安裝資料夾

有些遊戲，尤其是未透過 Steam 發行的作品，會把存檔寫在執行檔旁，或遊戲目錄內的 `Saves`、`SaveData`、`Profile` 子資料夾中。如果 AppData 裡看起來都不對，先開啟安裝目錄並掃描這些名稱，再繼續往下找。這裡也常能找到有時會直接指向存檔路徑的設定檔。

## 快速鎖定確切資料夾的方法

當有根據的猜測沒能命中時，改用搜尋。這些方法不分引擎都適用，也是經常排解存檔問題的玩家所用的同一套做法。

| 方法 | 怎麼做 | 最適合 |
|---|---|---|
| 副檔名搜尋 | 搜尋磁碟中的 `*.sav`、`*.dat` 或 `*.json` | 把數千個檔案縮小到少數幾個 |
| 依修改日期排序 | 將搜尋結果依日期排序，最新在前 | 確認遊戲剛寫入哪個檔案 |
| Steam 檔案瀏覽器 | 對遊戲按右鍵 → 管理 → 瀏覽本機檔案 | 找出與遊戲存放在一起的可攜式存檔 |
| 檔案監控工具 | 在遊戲內儲存時監看寫入活動 | 鎖定冷門或遭改名的路徑 |
| 遊戲內選單檢查 | 尋找「save folder」或「open directory」選項 | 會自行揭露路徑的遊戲 |

檔案監控做法值得一提，因為它很果斷。執行輕量的監控工具，在遊戲中儲存，然後觀察哪個目錄出現寫入事件。出現的那個就是答案，毫不含糊——即使開發者把資料夾改名成完全認不出來的名稱也一樣。

如果你不想安裝任何東西，就用低科技版本：記下確切時間，儲存遊戲，然後搜尋最近幾分鐘內修改過的檔案。速度較慢，但同樣有結論。

## 《Village in the Shade》存檔位置在 macOS 與 Linux 上

Mac 與 Linux 玩家面臨同樣問題，但資料夾慣例不同。在 macOS 上，Library 資料夾預設為隱藏，這讓很多人卡住。按住 **Option** 鍵並開啟 Finder 的 **Go** 選單，或使用 **Go to Folder** 並直接貼上路徑。

| 平台 | 常見存檔路徑 |
|---|---|
| macOS（原生） | `~/Library/Application Support/<Game>` |
| macOS（Unity） | `~/Library/Application Support/<Studio>/<Game>` |
| Linux（原生） | `~/.local/share/<Game>` |
| Linux（Unity） | `~/.config/unity3d/<Studio>/<Game>` |
| 透過 Proton 的 Linux | `steamapps/compatdata/<AppID>/pfx/drive_c/users/steamuser/` |

Proton 路徑值得加入書籤。當 Windows 遊戲透過 Linux 或 Steam Deck 上的相容層執行時，存檔會位於虛擬 Windows 磁碟中，而不是你的家目錄。從那個 `steamuser` 資料夾開始，依循你在真實 Windows 機器上會用的相同 AppData 結構即可。備份 Steam Deck 的遊玩進度，表示要從該前綴複製，而不是從遊戲安裝資料夾複製。

## 圍繞存檔資料夾建立備份習慣

找到一次《Village in the Shade》存檔位置很有用。真正能保護進度的，是永久記住它，並建立一套固定流程。敘事導向遊戲的存檔通常很小——往往最多只有幾 MB——所以沒有理由對備份吝嗇。

| 頻率 | 動作 | 花費心力 |
|---|---|---|
| 每次遊玩前 | 將存檔資料夾複製到以日期命名的子資料夾 | 不到一分鐘 |
| 每週 | 將備份資料夾同步到雲端儲存空間 | 設定好後自動進行 |
| 重大選擇前 | 複製檔案並依該分支重新命名 | 幾秒鐘 |
| 完成遊戲後 | 將最終存檔連同你的筆記一起封存 | 一次性 |

簡單的命名慣例能讓一切保持井然有序：`save-backup-YYYY-MM-DD-HHMM`。依字母排序，備份就會自動按時間排列。如果你保留多輪遊玩，加上簡短標籤——`chapter4-beforechoice` 比 `backup2` 告訴你更多資訊。

### 還原時不破壞原有資料

還原只是反過來操作，但有一條規則：先關閉遊戲。遊戲經常在結束時重寫存檔資料，因此在處理程序執行期間複製檔案，可能會覆蓋你的還原內容，或產生只寫了一半的檔案。完整退出遊戲，確認處理程序已結束，再將備份貼到資料夾中並重新啟動。如果遊戲會同步到雲端服務，重新啟動前先確認哪份副本會勝出——過期的雲端版本可能會默默取代你剛還原的檔案。

## 疑難排解：當存檔位置不在你預期的地方

社群對獨立遊戲的回報經常提到存檔似乎消失。幾乎每個案例中，資料其實都存在，只是路徑在某個意想不到的地方。在假設任何東西遺失之前，先依下表逐項檢查。

| 症狀 | 可能原因 | 修正方式 |
|---|---|---|
| 到處都找不到存檔資料夾 | 存檔存放在安裝目錄中 | 檢查遊戲自己的資料夾 |
| 資料夾存在但是空的 | 僅雲端或沙盒儲存 | 暫時停用雲端同步並重新儲存 |
| 檔案存在但遊戲忽略它 | 版本或設定檔不符 | 確認檔名完全一致 |
| 更新後存檔重置 | 版本之間路徑改變 | 搜尋新的資料夾並移轉 |
| 兩份互相衝突的存檔 | 雲端與本機分岔 | 比較時間戳記，保留較新的那一份 |

若想取得第二意見，社群維護的參考資料如 [PCGamingWiki 的 Village in the Shade 條目](https://www.pcgamingwiki.com/wiki/Village_in_the_Shade) 有時會列出存檔路徑與設定細節，不過小型作品的 wiki 涵蓋範圍可能不完整，或暫時無法使用。當這類頁面資訊不足時，論壇與 Steam 討論區分享的玩家經驗往往是最快的來源——但採取行動前，請先對照自己的檔案系統驗證你讀到的任何內容。

## 常見問題

**《Village in the Shade》存檔位置在一般 Windows PC 上哪裡？**
這取決於引擎。Unity 遊戲通常將資料存放在 `AppData\LocalLow`，Unreal 作品存放在 `AppData\Local\<Game>\Saved\SaveGames`，Godot 遊戲則存放在 `AppData\Roaming`。儲存後立刻搜尋磁碟中最近修改的 `.sav` 或 `.dat` 檔案，就能在一分鐘內確認確切資料夾。

**我可以把存檔移到另一台電腦嗎？**
可以。將整個存檔資料夾——不只是最新的檔案——複製到新機器上的相同相對路徑。有些遊戲還會在存檔旁存放獨立的設定或設定檔，缺少它可能讓遊戲把你的進度視為無效。

**為什麼更新後我的存檔消失了？**
更新偶爾會改變內部資料夾名稱，或將資料移轉為新格式。檢查 AppData 底下是否出現名稱略有不同的新資料夾，並在裡面尋找時間戳記符合舊存檔的檔案。保留有日期的備份，能讓這種情況可回復，而不是致命打擊。

**啟用 Steam Cloud 後，《Village in the Shade》存檔位置會改變嗎？**
雲端同步不會移動本機檔案；它會將檔案鏡像到 Steam `userdata` 目錄下的遠端副本。知道本機的《Village in the Shade》存檔位置仍然很重要，因為當雲端與本機版本不一致時，那正是你會編輯、備份與還原的副本。
